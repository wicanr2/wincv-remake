# 字典資料(`*.txt.dat` / `*.txt.idx`)

WinCV 隨附四份字典資料。**四份的分隔字元都不一樣**,不能用同一套規則解。

| 檔案 | 內容 | 分隔 | 筆數(實測) |
|---|---|---|---|
| `eng.txt.dat` | 英文單字 → 中文解釋 | `0x01` | 155,981 |
| `kk.txt.dat` | 英文單字 → KK 音標 | `0x01` | 70,125 |
| `chi.txt.dat` | 國字 → 發音與解釋 | 空白 | 13,471 |
| `origin-verb.txt.dat` | 動詞變化形 → 原形 | `*` | 522 |

格式一律是每行 `<鍵><分隔><值>`,內容 Big5。

`chi.txt` 用空白分隔有 image 內的字串佐證:
`0x82156` 是「國字及解釋間須以空白隔開」——那是原版自己的編輯提示。

`eng.txt`(不含 `.dat`)是同一份資料的純文字版,沒有 `0x01`,
單字與解釋直接相接。`.dat` 是加了分隔字元的版本。

## 重複鍵

同一個單字會出現多次(不同詞性、不同來源)。**要接起來,不要後面蓋掉前面** ——
`apple` 有兩筆就是兩個意思,蓋掉會少一半。

## KK 音標的符號編碼

`kk.txt.dat` 的值長這樣:

```
a cappella   ?%E+>A#S+
a la king    ?%S+>E"R
```

用的是 ASCII 可見字元(`+ > - V ) Q % # "` …),但顯示出來應該是音標符號。
**對應關係還沒查出來**(CLAUDE.md 假設 A11)。原版可能有一張替換表,
也可能有一個把這些碼位換成音標字形的專用字型。目前 remake 原樣顯示。

## `.idx` 索引

原版另有索引檔,結構解到一半:

```
0x00       BYTE   0x64(100,用途不明,四個檔都一樣)
0x01       BYTE   n1 = 第一層字元數
0x02..     n1 個 BYTE:所有鍵的**第一個字元**,已排序
之後       對每個第一層字元:BYTE m + m 個 BYTE(第二層字元)
再之後     位移表(欄位寬度與語意未確認)
```

`eng.txt.idx` 的第一層是 67 個字元(`!` 到 `~`),
`kk.txt.idx` 是 26 個(`A`–`Z`)。

**remake 不用它。** 最大的一份 `.dat` 也只有 5.6 MB,載進來自己建索引更單純,
也不必依賴一個沒完全解出來的格式。解到這裡是為了記錄,不是為了使用。

## 怎麼驗

`internal/dict` 的測試直接吃原版資料:

```
eng=155981 kk=70125 chi=13471 verb=522
```

以及幾個行為:重複鍵要接起來、`abided` 要能透過 `origin-verb` 找到 `abide`
的解釋(原版的 origin-verb 裡有 154 個「自己不在 eng.txt 裡」的變化形)。
