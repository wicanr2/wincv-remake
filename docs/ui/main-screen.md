# 主畫面版面(原版實測)

量測對象是 Wine 底下跑的原版 `wincv.exe`,視窗 client area **792 × 506**。
重跑方式:

```bash
tools/oracle-measure.sh docs/ui/oracle-window.png 18
```

這支腳本會問 X 拿視窗幾何、只截視窗本體(不含外框與標題列),
並印出 Wine 選了哪些字型。

## 字型:原版同時要兩種尺寸

Wine 的 font trace:

```
select_font Chosen: L"cvga Regular" (L"C:\wincv\wincv.fon")
get_fontsig pix_h 15 charset 255   ← OEM_CHARSET,半形
get_fontsig pix_h 16 charset 136   ← CHINESEBIG5,全形
select_font Chosen: L"System Regular" (Z:\usr\share\wine\fonts\cvgasys.fon)
```

半形要 15 px、全形要 16 px。`cvgasys.fon` 是 Wine 給**選單列**用的 System 字型,
與檔案清單無關。

`cvga.fon` 自己的 `dfPixHeight` 是 15、`dfExternalLeading` 是 **0** ——
多出來的那一列不是字型要的,是程式拿全形字的高度當列高。

## 格點

以樣板比對(拿真實的 `cvga` 字模去截圖上找完全吻合的位置)量出來:

| 項目 | 值 |
|---|---|
| 格子大小 | **8 × 16** px(字模 8 × 15,靠上對齊,下方留一列) |
| 欄起點 | x = 34,間距 8,最右一格 x = 770 → **93 欄** |
| 捲軸 | x = 775..791(17 px) |
| 前景 / 背景範例 | 檔名列 `#C0C0C0` on `#000000` |

列的位置(y 為該列第一條掃描線):

| y | 內容 |
|---|---|
| 0..19 | 選單列(Win32 控制項,比例字型) |
| 22..38 | 工具列(Win32,含圖示) |
| 40 | 路徑列 `C:\wincv\*.*` + 位置 + 標記統計(1 列) |
| 56, 72, …, 328 | 檔案清單(**18 列**,間距 16) |
| 344..345 | 2 px 分隔(上白 `#FFFFFF`、下 `#C5C5C5`) |
| 346, 362 | 狀態列(2 列) |
| 378 起 | 預視窗格(8 列 × 16 = 128 px) |

檔案清單的第一欄(x = 34)是游標與標記的指示欄,檔名從 x = 42 開始。

## 每一欄的顏色(逐格量出來的)

以 `tools/celldiff.py` 把原版截圖與重製版切成同一套格點,逐格比對量出來的。
這些值在畫面上一眼看不出差別,但寫成 `internal/browser.DefaultTheme()` 的
每一個欄位:

| 位置 | 顏色 | 備註 |
|---|---|---|
| 最左邊的指示欄(第 0 欄) | `#000080` | **游標經過也不變** —— 游標的底色從第 1 欄才開始 |
| 路徑 | `#FFFF00` | |
| 路徑尾巴的 `*.*` | `#00FF00` | 與路徑不同色 |
| 右邊的「第幾筆 / 共幾筆」 | `#C5C5C5` | 不是檔案清單那個 `#C0C0C0` |
| `標記:` 後面的兩個數字 | `#FFFF00` | |
| 目錄總位元組 | `#FFFFFF` | |
| 目錄 | `#14BE00` | image 裡是獨立的一個 word,不是 ltgreen `#00FF00` |
| 一般檔案 | `#C0C0C0` | 副檔名另有配色,見 `internal/app/filecolor.go` |
| 日期 | `#00FF00` | **固定綠色,游標列上也不變** |
| 時間、大小 | 跟著檔案自己的顏色 | magenta 的檔案連時間都是 magenta |
| 長檔名欄 | `#C0C0C0` + **底線** | 底線畫在格子的最後一條掃描線(第 15 條) |
| 游標列 | 白字配 `#800000` | 不是反白 |
| 狀態列第一列 | `#FFFF00` on `#000080` | 游標檔案照清單的欄位再排一次 |
| 狀態列的「剩餘」 | `#C5C5C5` | 接在時間欄之後,不是靠右對齊到畫面邊緣 |
| 狀態列第二列 | `#FFFFFF` on `#000080` | 完整檔名 |

`#C5C5C5` 是 `LTGRAY` 在 image 裡的**第二個**定義(0x50210);
檔案清單用的是 0x1dc40 的 `#C0C0C0`。兩個定義都活著,不是同一個 word 被改過。

## 比對結果

```bash
tools/go.sh run ./cmd/celldump -app original/app -cols 93 -rows 21 -keys Down \
    -o docs/ui/celldiff-remake.png
tools/celldiff.py docs/ui/oracle-window.png docs/ui/celldiff-remake.png \
    --ox 34 --oy 40 --cols 92 --rows 19
```

比的是同一個目錄(原版的 `C:\wincv` = 這裡的 `original/app`),游標放在同一列。
狀態列那兩列要另外對:原版被 2 px 的分隔線往下推,落在 y=346 / 362,
不在 `oy=40` 起算的 16 px 格點上。

| 範圍 | 格數 | 相同 | 版面差 | 屬性差 | 像素差 |
|---|---|---|---|---|---|
| 路徑列 + 清單 + 兩列狀態列 | 1932 | 1647(85.2%) | 74 | 16 | 195 |
| 只看檔案清單 18 列 | 1656 | 1443(87.1%) | 38 | **0** | 175 |
| 狀態列第二列 | 92 | **92(100%)** | 0 | 0 | 0 |

**檔案清單的屬性差是 0**,狀態列第二列連字模都完全相同 ——
三級驗收的第二級(屬性等價)在這兩處成立,第二列連第三級(像素等價)也成立。

剩下的差異多半是**資料不同**而不是畫錯:

- 檔案的修改時間不一樣(原版那份是 Wine 裡的複本)。
- Wine 把長檔名顯示成 8.3 大寫短名(`BIG5~X5T TXT`),重製版顯示原名。
- 「剩餘」的可用空間會隨時間變動;**總容量兩邊都是 1,875,626MB**,單位與換算對得上。
- 狀態列第一列的 4 格屬性差是「剩餘」那兩個全形字:Wine 用系統字型畫、帶消鋸齒,
  重製版是點陣字。這是 Wine 的算繪差異,不是版面差異。

三個原本缺的東西現在都有了,但實作方式與原版不同,原因記在下面:

| | 原版 | 重製版 |
|---|---|---|
| 2 px 分隔線 | 插在清單與狀態列**之間**的額外 2 px,整個版面因此不是等高格點 | 畫在狀態列自己的前兩條掃描線(`cell.Cell.Rule`)。格點保持等高 —— cell 是唯一的繪圖介面,不為 2 px 破例 |
| 捲軸 | Win32 scrollbar 控制項,17 px,系統顏色 | 最右邊一欄格子:上下箭頭 + 滑塊,滑塊長度與位置反映看得到的比例與捲到哪裡 |
| 磁碟窗格 | Win32 工具列那一帶的獨立窗格,可調大小(設定裡的「調整 磁碟視窗、預視視窗 的大小」) | 清單左邊的 10 欄格子,`Alt-D` 開關、`Tab` 切焦點 |

三者都做不到像素等價(原版那兩個是 Win32 控制項,用的是系統顏色與比例字型),
做到的是功能等價。原版磁碟窗格的資料結構在 image 裡看得到:
`>DISKBUF-PATH` / `>DISKBUF-ATTRIB` / `>DISKBUF-LABEL` 三個欄位存取子
(`docs/re/symbols.tsv`),重製版的 `vfs.Drive` 就是照這三個欄位開的。

## 重製版對應

`internal/render` 的 `LineGap = 1` 就是上表那一列:`CellH = 字身高 + 1`。
`cmd/celldump -app -cols 93 -rows 21` 畫出來的格子與原版同尺寸。

尚未做的部分:選單列與工具列(重製版用 `F1` 自繪選單取代)、
左側磁碟欄、預視窗格、捲軸。這些差異記在 README 的對照表。

## 這份量測推翻過的說法

早期的結論是「oracle 截圖只能當版面與配色真值,不能當字模真值」,
理由寫成「Wine 用自己的 `cvgasys.fon`(16 px)替換掉 `cvga`(15 px)」。
兩點都不成立:Wine 確實載入了 app 的 `cvga`,而當初樣板比對之所以零命中,
是因為 `tools/xwd2png.py` 當時把每像素寫死 4 bytes,容器裡的 Xvfb 卻是 24 bpp,
通道以 3 為週期輪轉。轉檔工具修好之後,每個字元都剛好命中一次。
